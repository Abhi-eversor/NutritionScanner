# NutritionScanner

NutritionScanner is a research prototype for detecting nutrition panels on
Android, extracting their contents with on-device OCR, and optionally producing
general nutrition guidance from reviewed label data.

The root Android application deploys the proposed MobileNetV2-SSD detector.
The repository also includes the teacher/student training pipeline, compression
stages, saved MobileNet checkpoints, evaluation reports, and a separate YOLO
benchmark demonstration. Both applications include their deployed models;
building the apps does not require retraining.

## Scan workflow

The primary app uses CameraX for live framing and runs MobileNetV2-SSD again on
the captured photo. It crops the detected panel, reads it with bundled ML Kit
OCR, and translates to English when needed. The user reviews structured
nutrition fields before optionally requesting general guidance from Gemini.
Photos and OCR text are not stored as scan history. Dietary preferences and
health-profile flags are stored in local Android DataStore and can be cleared
in the app. Android backup is enabled in the primary app, so device settings
may also permit system backup of that data.

The optional YOLO app uses a different detector and a manual crop editor,
followed by reviewed text and free-text guidance. It is retained as a benchmark
demonstration, not a replacement for the proposed MobileNet deployment.

## Repository layout

- `app/` contains the primary Android application using MobileNetV2-SSD.
- `nutrition_detector_model_128_07mb_v5/code/` contains the training,
  distillation, pruning, quantization, and evaluation pipeline.
- `nutrition_detector_model_128_07mb_v5/nutrition_detector_run_128_07mb/`
  contains saved MobileNetV2-SSD checkpoints, exported models, and metrics.
- `yolo26_training_results2/` contains retained YOLO configurations, CSV
  results, curves, and confusion matrices. Extra weights, prediction images,
  and dataset-image montages are excluded from Git.
- `NutritionScannerV5Demo/` is a separate Android application that packages
  the YOLO benchmark detector and supports manual crop confirmation.

- `docs/EXPERIMENTS.md` records dataset references, current training
  configuration, experimental stages, and limitations of the saved evidence.
- `docs/ARTIFACTS.md` explains the retained models and local archive policy.

MobileNet stage checkpoints remain available for evaluating compression stages.
YOLO checkpoint copies and rendered dataset images were preserved in a local
archive outside the repository; this archive is not a public download.

## Quick start

Install JDK 17 and Android SDK Platform 36. Open the repository root, the
folder containing this file and `gradlew`, in Android Studio. Select the root
`app` configuration to run the primary application on an Android 8.0+ device.

```powershell
# Windows PowerShell, from the repository root
.\gradlew.bat :app:assembleDebug
```

```bash
# macOS or Linux, from the repository root
./gradlew :app:assembleDebug
```

To build the benchmark app, run the same command inside
`NutritionScannerV5Demo/`. Both apps have the same application ID, so installing
one replaces the other on a device.

The Gemini guidance stage is optional. Use `local.properties.example` as a
template for a local `GEMINI_API_KEY`; do not overwrite an existing
`local.properties` generated by Android Studio, and never commit a real key.
Each Android project has its own local configuration. A configured key is
embedded in its APK: keep keyed APKs private. The repository contains source
and models rather than installable packages.

For complete, cross-platform build instructions, the optional YOLO demo,
Kaggle training reproduction, evaluation, and troubleshooting, see
[RUN_PROJECT.md](RUN_PROJECT.md).

## Training pipeline

The MobileNetV2-SSD pipeline is in
`nutrition_detector_model_128_07mb_v5/code/`. It expects a compatible
TFRecord export and is documented in
[KAGGLE_RUN.md](nutrition_detector_model_128_07mb_v5/code/KAGGLE_RUN.md).

The stages train a MobileNetV2-SSD teacher, distil a smaller student, prune
expansion channels and fine-tune, then apply quantization-aware training and
export the INT8 TFLite detector. The current configuration uses a 128 x 128
input and a reported two-T4 training setup. Recovered Roboflow version-2
export records and matching split counts identify candidate dataset sources;
see [dataset records](docs/provenance/README.md). Exact historical input
identity, the original training environment, and some evaluation reports
remain unverified; see [experimental provenance](docs/EXPERIMENTS.md) before
comparing results.

## Saved results and evidence

| Saved report | Final MobileNet INT8 mAP@0.5 | Images |
| --- | ---: | ---: |
| Pipeline test JSON | 0.9237 | 121 |
| External test JSON | 0.7166 | 45 |

These figures describe detector evaluation on the saved splits, not OCR,
nutrition-guidance quality, or measured Android latency. The separate YOLO
CSV reports mAP@0.5 of 0.9606 and mAP@0.5:0.95 of 0.7445, but its split
identity is not recorded well enough to establish a controlled comparison.

The historical notes report external-test F1 of **0.6966**, while the saved
external JSON contains **0.6316**. The reported confidence-0.30 sweep result
also lacks its original sweep file. Both accounts are preserved and clearly
identified in [MODEL_AND_DEMO_NOTES.md](MODEL_AND_DEMO_NOTES.md); the discrepancy
is unresolved. No model, metric JSON, or result CSV was changed during
repository preparation.
